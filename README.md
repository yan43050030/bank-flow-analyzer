# 银行流水资金统计工具 v2.0

> 纯本地运行 · 零联网 · 数据不外泄 · 宁少算不重复

通过银行交易流水分析个人经济状况。自动处理**存取反复**和**理财循环**，给出保守的资金估算。

## 核心功能

| 功能 | 说明 |
|------|------|
| **交易自动分类** | 识别现金存取、理财交易、消费支出、转账 4 大类 |
| **存取链配对** | 多次存取自动配对，按最小金额统计，避免资金来回倒腾重复算 |
| **理财买卖配对** | 买入↔赎回自动匹配，循环买入只算一次本金，利息/收益单独统计 |
| **未赎回理财追踪** | 买入后未配对的理财计入未赎回余额 |
| **消费统计** | 自动识别消费支出（支付宝/微信/美团/POS等） |
| **历史峰值估算** | 保守估算该银行卡的资金最高通过量 |

### 统计输出格式

```
此张卡:
├── 历史最高资金    10,000,000 元
├── 卡内余额         2,000,000 元
├── 理财未赎回       3,000,000 元
├── 消费支出         1,000,000 元
├── 净转出           4,000,000 元
├── 存取经过         5,000,000 元（配对成功部分）
└── 理财获利           200,000 元
```

## 算法示例

### 存取反复

```
存100万 → 取100万 → 存200万 → 取150万 → 存100万

配对: 取100万←存100万, 取150万←存200万(剩余50万)
经过: 250万（配对部分）
净存: 150万（未配对存款-未配对取款）
峰值: 200万（存200万时的余额高点）
```

### 理财循环

```
存100万 → 买理财100万 → 赎100.1万 → 再买100万 → 赎100.1万

配对: 买100↔赎100.1(利息0.1), 买100↔赎100.1(利息0.1)
本金: 100万（两次买入是同一笔钱，不重复算）
获利: 0.2万（两次利息合计）
未赎回: 0
```

## 多设备协作开发

代码用 GitHub 同步，**真实案件数据绝不入库**。

### 首次拉取（新设备）

```bash
git clone https://github.com/yan43050030/bank-flow-analyzer.git
cd bank-flow-analyzer
pip install -r requirements.txt
```

### 日常工作流

```bash
# 开始工作前 — 拉最新
git pull --rebase origin main

# 改代码 → 提交
git add <具体文件名>           # 不要用 git add . / -A，避免误传数据
git commit -m "feat: 描述改动"
git push origin <分支名>

# 切换设备前 — 务必先推送
git status                     # 确认无未提交改动
git push
```

### 数据隔离纪律

| 类型 | 是否入库 | 存放位置 |
|------|---------|---------|
| 代码 (`.py`) | ✅ 入库 | 仓库内 |
| 合成测试数据 (`test_*.csv`) | ✅ 入库 | 仓库内 |
| 真实流水 (`*.xlsx`/`*.xls`) | ❌ 严禁 | 本地加密盘 `../case-data/` |
| 导出结果 (`资金统计结果*.xlsx`) | ❌ 严禁 | 本地加密盘 |
| 截图、证据 | ❌ 严禁 | 本地加密盘 |

建议目录结构：

```
~/work/
├── bank-flow-analyzer/        ← Git 跟踪（云端同步）
└── case-data/                  ← 本地加密盘，绝不入 Git
    ├── 2024-XX案/
    │   ├── 流水原件.xlsx
    │   └── 分析结果.xlsx
    └── 2024-YY案/
```

### 多设备冲突处理

如果两台设备都改了同一文件：

```bash
git pull --rebase origin main   # 先拉
# 若有冲突，解决后：
git add <冲突文件>
git rebase --continue
git push
```
